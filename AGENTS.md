# Documentation project instructions

> First-time setup note: this repository aggregates AmazeCC's developer documentation via the Mintlify multirepo action. Read this whole file before touching anything.

## How this repository works

- This repo is a **site shell**: it holds the Mintlify site configuration, brand assets, and two hand-written pages (`index.mdx`, `quickstart.mdx`).
- All real documentation lives in the [AmazeCC repo](https://github.com/AmazeContinuityProjects/AmazeCC) under `docs/`. The `Aggregate docs` workflow copies `AmazeContinuityProjects/AmazeCC:docs/` into `amazecc/` here.
- `docs.base.json` + the child's `docs.json` → the action generates **`docs.json`** (never edit it directly — the next sync overwrites it), same for `amazecc/`.

## Editing rules

- **Handbook edits** → go to the AmazeCC repo (`docs/…`). This repo's PRs only change: `docs.base.json`, `index.mdx`, `quickstart.mdx`, `logo/`, `favicon.svg`, workflows, `README.md`, `AGENTS.md`.
- **Site structure** (tabs/pages order/landing) → `docs.base.json`. The navigation groups for the handbook live in the child repo (`docs/docs.json`, generated by `grounding/gen-child-docs.mjs`).
- Don't rename or delete files inside `amazecc/` — they're regenerated each sync.
- Keep links between this repo's pages and the handbook prefixed with `/amazecc/`.

## Mintlify reference

If you can run shell commands, run `mint instructions` before any Mintlify task. The CLI is `mint` (`npm i -g mint`). Key files:

- `docs.base.json` → `docs.json` (generated)
- MDX pages with YAML frontmatter (`title`, `description`)
- Components: `Card`, `CardGroup`, `Steps`, `Note`, `Tip`, `Callout`, `Accordion`

## Style preferences

- Active voice, second person, sentence case headings
- Bold for UI elements; code formatting for filenames, commands, and paths
- Keep "Start here" tab pages short; the handbook carries the depth

## Content boundaries

- The AmazeCC handbook is the canonical reference; this site is a view of it, nothing more
- No internal credentials, hostnames, or PostHog keys anywhere in committed files — they belong in AmazeCC-API
